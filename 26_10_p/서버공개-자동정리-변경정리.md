# 서버 공개 · 지난 글 자동 정리 (변경 정리)

리눅스 노트북에서 서버를 **계속 켜 두고 인터넷 어디서나 접속**되게 만들었고,
**기간이 지난 공모전 · 팀원 모집 · 스터디가 알아서 지워지게** 했다.

| 한 일 | 핵심 |
| --- | --- |
| 1. 원클릭 공개 스크립트 | `./서버공개하기.sh` 한 번이면 설치 → 빌드 → 서비스 등록 → 공개 주소 발급 |
| 2. 공모전이 안 보이던 문제 | 공지 수집이 한 번도 안 돌았던 것. 처음 설치 때 바로 수집하게 함 |
| 3. 지난 글 자동 정리 | 서버가 1시간마다 정리. 학교 공지는 본문에서 마감일을 뽑아 기준으로 씀 |
| 4. 스터디 종료일 | 스터디를 만들 때 종료일(선택)을 정하면 그날이 지난 뒤 자동 삭제 |
| 5. 보안 점검 | `smtp.env` 가 git · 웹으로 새지 않는지 확인, 파일 권한을 600 으로 |

실행 방법 전체는 [서버실행방법-리눅스.md](서버실행방법-리눅스.md) 에 있다.

## 1. 원클릭 공개 스크립트 (`서버공개하기.sh`)

```sh
./서버공개하기.sh          # 처음 설치 ~ 공개 주소 발급까지
./서버공개하기.sh --off    # 공개 주소만 닫기 (서버는 이 컴퓨터에서 계속 돈다)
```

기존 스크립트들을 순서대로 부른다. 이미 된 단계는 건너뛰므로 몇 번을 다시 돌려도 되고,
코드를 고친 뒤 반영할 때도 이것만 다시 돌리면 된다.

| 단계 | 하는 일 |
| --- | --- |
| 1 | `server` · `db.env` 가 없으면 `scripts/setup-linux.sh` (패키지 · 빌드 · DB). 있으면 `make` 만 |
| 2 | 관리자 계정이 없으면 학번 · 이름 · 비밀번호를 물어 만든다 (Enter 로 건너뛰기) |
| 3 | `scripts/install-service.sh --keep-awake` — 부팅 시 자동 시작, 죽으면 재시작, 노트북이 잠들지 않게 |
| 3+ | 게시물이 하나도 없으면 학교 공지를 바로 한 번 수집 (2장) |
| 4 | Tailscale Funnel 을 켜고 공개 주소(`https://<컴퓨터이름>.<tailnet>.ts.net`)를 출력 |

`smtp.env` 가 비어 있으면 회원가입 인증 메일이 안 나간다고 경고한다.

### 왜 Tailscale Funnel 인가

| 방법 | 접속하는 사람 | 주소 |
| --- | --- | --- |
| **Tailscale Funnel** (선택) | 아무것도 안 깔아도 됨 | 고정 HTTPS 주소, 재부팅해도 유지 |
| 일반 Tailscale | 각자 Tailscale 설치 + 초대 필요 | `http://100.x.x.x` |
| Cloudflare 임시 터널 | 아무것도 안 깔아도 됨 | cloudflared 를 켤 때마다 주소가 바뀜 |
| 공유기 포트 포워딩 | 아무것도 안 깔아도 됨 | 집 IP 노출, HTTPS 없음 |

Funnel 은 도메인을 사지 않아도 고정 주소와 HTTPS 가 붙는다. 처음 한 번 Tailscale 관리 콘솔에서
"Funnel 허용" 링크를 승인해야 한다. 무료 플랜은 대역폭 제한이 있지만 시연 · 테스트에는 충분하다.

### 주의: VSCode 터미널에서는 sudo 가 안 된다

VSCode 를 **snap** 으로 설치하면 VSCode 자체가 "no new privileges" 상태로 돌아서,
그 안의 터미널(과 Claude Code)에서는 sudo 가 막힌다.

```
sudo: The "no new privileges" flag is set, which prevents sudo from running as root.
```

**Ctrl+Alt+T** 로 연 일반 터미널에서 실행한다. 스크립트도 이 상태를 감지해 안내하고 멈춘다.
근본 해결은 snap 대신 Microsoft 의 `.deb` 판 VSCode 를 까는 것.

## 2. 공모전 정보가 안 보이던 문제

서버는 정상이었고 `/api/posts` 가 빈 목록을 돌려주고 있었다. 원인은 **공지 수집이 한 번도 안 돈 것**.

- 수집 타이머(`sku14-crawl.timer`)는 매일 06:00 에만 돈다. 서비스를 막 등록했으니 첫 실행이 다음 날 아침이었다.
- `scripts/run-server.sh --crawl` 로 직접 돌려 학교 공지 136건을 올렸다.
- 같은 일이 없게 `서버공개하기.sh` 가 서버를 띄운 뒤 게시물이 0건이면 바로 한 번 수집한다.

## 3. 지난 글 자동 정리

### 규칙

마감일 **당일까지는 남고**, 그날이 지나면 지운다.

| 대상 | 지우는 때 | 함께 지워지는 것 |
| --- | --- | --- |
| 공모전 (`posts`) | 마감일이 지나면 | 댓글, 대상 학과, AI 분석 (ON DELETE CASCADE) |
| 마감일을 모르는 학교 공지 | 게시일로부터 **60일** 뒤 | 위와 같음 |
| 팀원 모집 (`recruits`) | 마감(closed)했거나 마감일이 지나면 | 댓글, 태그, 좋아요 |
| 스터디 (`study_groups`) | 종료일이 지나면 (종료일이 없으면 안 지움) | 멤버 목록 |
| 공지 기록 (`notices`) | 수집 기간(730일) + 30일보다 오래되고 게시물이 없는 것 | — |

- 공모전이 지워져도 그 공모전에 연결된 팀원 모집글은 남는다 (`post_id` 만 NULL).
- 사람이 직접 쓴 공모전 글은 마감일이 없으면 지우지 않는다 (60일 규칙은 학교 공지에만).
- 지운 공모전의 공지 기록(`notices`, status = published)은 남겨 두므로 **다음 수집 때 다시 올라오지 않는다.**
- 60일은 `app_config` 의 `cleanup.no_deadline_days` 로 바꿀 수 있다.

### 언제 도나

| 때 | 어디서 |
| --- | --- |
| 서버가 켜질 때 한 번, 이후 **1시간마다** | 웹 서버 안의 백그라운드 스레드 (`cleanup_start`) |
| 매일 06:00 공지 수집 직후 | `server --crawl` |
| 손으로 | `scripts/run-server.sh --cleanup` |

서버 안에서 도므로 systemd 가 없는 Windows 에서도 동작한다.
DB 연결은 원래 잠금으로 보호되는 공유 연결이라 스레드를 하나 더 둬도 안전하다.

### 학교 공지의 마감일 추출

수집한 공지는 마감일(`deadline`)이 **모두 비어 있었다** (136건 전부). 그래서 공지를 게시할 때
본문에서 마감일을 짐작해 넣게 했다 (`notice_guess_deadline`, `src/crawler.c`).
이미 올라와 있던 게시물은 서버가 켜질 때 한 번 채운다 (`cleanup_backfill_deadlines`).

1. 다음 말이 있는 줄을 찾는다. 앞 묶음에서 날짜를 찾으면 뒤 묶음은 보지 않는다.
   1. `접수` `응모` `모집 기간` `공모 기간` — 접수 기간 그 자체
   2. `신청` `제출` `마감` `기한` `모집` — "결과보고서 제출" 같은 뒷일정이 섞일 수 있어 2순위
   3. `기간` `일정` `일시`
2. 그 말 뒤의 날짜를 모두 읽고 **가장 늦은 날**(기간의 끝)을 고른다.
3. 게시일보다 7일 넘게 앞이거나 400일 넘게 뒤인 날은 버린다 (행사 연혁 등).

읽을 수 있는 날짜 형식:

| 원문 | 결과 (게시일 2026-09) |
| --- | --- |
| `접수 : 2026. 09. 28. ~ 2026. 10. 22.` | 2026-10-22 |
| `기간: 2026.9.28.(월)~10.31.(토)` | 2026-10-31 (뒤 날짜는 앞 날짜의 연도를 따름) |
| `기간: 9.3.(목)09:00~11.8.(일)24:00까지` | 2026-11-08 (`09:00` 같은 시각은 무시) |
| `접수기간: ~2026.10.12. (월) 까지` | 2026-10-12 |
| `공모기간 : 26년 6월 1일(월) ~ 10월 2일 (금)` | 2026-10-02 (두 자리 연도) |
| `접수기간 : ’26. 03. 26.(목) ~ 06. 21.(일)` | 2026-06-21 (`’26.` 표기) |
| 12월 공지의 `1.10. 까지` | 이듬해 1월 10일 (게시일보다 반년 넘게 앞이면 이듬해로) |

`02-940-7114` 같은 전화번호는 날짜로 보지 않는다 (월부터 시작하는 날짜는 `-` 구분자를 받지 않음).

**실제 데이터로 시험한 결과**: 136건 중 124건에서 마감일을 찾았다. 처음에 틀렸던 4건
(결과보고서 제출일을 마감으로 잡음, 두 자리 연도, `’26.` 표기 등)은 원문과 대조해 고쳤다.
나머지를 한 건씩 대조하지는 않았다. 틀린다면 늦게 잡는 쪽(글이 더 오래 남음)이 되도록 설계했다.

### 스터디 종료일

- 스터디 만들기 화면에 **종료일 (선택)** 입력을 추가했다. 오늘보다 앞 날짜는 고를 수 없다 (서버에서도 거부).
- 목록 카드에 `~ 2026-12-31 종료`, 상세 화면에 `종료일` 이 보인다.
- API: `POST /api/studies` 가 `end_date` 를 받고, 목록 · 상세 응답에 `end_date` 가 붙는다 (없으면 null).
- DB 에 `study_groups.end_date DATE NULL` 열을 추가했다. **서버가 시작할 때 열이 없으면 스스로 추가**하므로
  (`cleanup_ensure_schema`) 쓰던 DB 에 SQL 을 따로 돌리지 않아도 된다.
  MySQL 8 은 `ADD COLUMN IF NOT EXISTS` 를 몰라서 `information_schema` 로 먼저 확인한다.

## 6. 반영 방법과 확인

코드를 받은 뒤 (일반 터미널에서):

```sh
make && sudo systemctl restart sku14     # 또는 ./서버공개하기.sh
journalctl -u sku14 -n 20
```

로그에 다음이 보이면 정상이다.

```
학교 공지 게시물 N건의 마감일을 본문에서 찾아 채웠습니다.
지난 글 정리: 공모전 N, 팀원 모집 N, 스터디 N건 삭제
```

> **처음 반영하면 지난 공모전이 한꺼번에 지워진다.** 되돌릴 수 없다.

이 노트북에서는 2026-10-11 21:39 에 반영했고, 미리 계산한 그대로 나왔다.

```
학교 공지 게시물 124건의 마감일을 본문에서 찾아 채웠습니다.
지난 글 정리: 공모전 127, 팀원 모집 0, 스터디 0건 삭제
```

136건 중 9건(마감 전 7건 + 마감일을 모르는 최근 공지 2건)이 남았다.

### 확인한 것 / 아직 안 한 것

- 확인: 빌드(경고 없음), `app.js` 문법 검사, 마감일 추출(실제 게시물 136건), 서버 시작 시 정리(위 로그)
- 아직: 1시간 뒤 두 번째 정리가 도는지, 스터디를 종료일과 함께 만들어 목록 · 상세에 보이는지

### 정할 수 있는 것

- 마감일을 모르는 학교 공지 보존 기간: 기본 60일 (`cleanup.no_deadline_days`)
- 팀원 모집글은 마감 버튼을 누르면 1시간 안에 사라진다. 며칠 남겨 두려면 마감 시각(`closed_at`) 열이 필요하다.
