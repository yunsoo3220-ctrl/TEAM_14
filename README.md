# 서경대학교 공모전 팀원 모집 커뮤니티 — 최종 결과 보고서

> TEAM_14 · 작업 기간 2026-09-29 ~ 2026-10-16 · 저장소 `TEAM_14/26_10_p`

---

## 1. 프로젝트 개요

### 1.1 한 줄 요약

에브리타임처럼 **서경대 구성원만 쓰는 커뮤니티**에서, 학교 공지에 올라온 **공모전을 자동으로 모아 학과별로 추천**하고,
학생끼리 **팀원을 찾아 모집·스터디·멘토링으로 이어 주고, 모인 팀이 채팅방에서 바로 이야기하게 해 주는** 웹 서비스다.

### 1.2 문제와 목적

| 문제 | 이 프로젝트의 해결 |
| --- | --- |
| 공모전 공지가 학교 홈페이지 공지사항 사이에 섞여 있어 찾기 어렵다 | 학교 홈페이지(WordPress REST API)에서 공모전·해커톤·대회 공지를 **자동 수집**, 제목 필터로 결과 발표·장학금 등은 걸러 냄 |
| 내 학과와 관련 있는 공모전이 무엇인지 알기 어렵다 | 외부 API 없이 서버 안에서 학습하는 **자체 추천 모델**(TF-IDF + Rocchio + 딥러닝 임베딩)로 학과별 관련도 0~100 |
| 공모전에 함께 나갈 팀원을 구하기 어렵다 | 관심 키워드·자기소개 기반 **팀원 모집 게시판**, 잘 맞는 회원 추천과 **참여 권유** |
| 팀이 모여도 연락할 곳이 따로 필요하다 | 모집글 팀·스터디·멘토링마다 멤버끼리만 쓰는 **채팅방** 자동 제공 |
| 아무나 댓글을 달면 대상이 아닌 학생의 글이 섞인다 | 관리자가 체크한 **대상 학과 학생만 댓글 작성** (열람은 누구나) |
| 외부인이 섞이면 신뢰도가 떨어진다 | **학교 이메일(@skuniv.ac.kr) 인증**을 거쳐야 가입 |

### 1.3 과제의 핵심 요구사항: 보는 것과 쓰는 것을 나눈다

1. 학생은 가입할 때 소속 학과를 하나 고른다 → `users.department_id`
2. 관리자가 공모전 게시물에 대상 학과를 체크한다 → `post_departments`
3. 댓글을 저장하기 직전에 서버가 그 학생의 학과가 대상에 들어 있는지 다시 확인한다

| 상황 | 결과 |
| --- | --- |
| 로그인하지 않음 | 글은 보이지만 댓글은 `401` |
| 관리자 | 항상 가능 |
| 대상 학과를 지정하지 않은 글 | 로그인한 누구나 가능 |
| 대상 학과 지정 글 + 해당 학과 학생 | 가능 |
| 대상 학과 지정 글 + 다른 학과 학생 | `403 department_not_allowed` |

판정은 `src/api_posts.c` 의 `can_comment()` **한 곳**에 모아 화면 표시와 실제 저장 양쪽에서 쓴다.
화면에서 입력창을 잠그는 것은 안내용일 뿐이고, **권한 판정은 전부 서버에서** 하므로 개발자 도구로 요청을 직접 보내도 우회할 수 없다.

## 3. 시스템 구조

```
 [브라우저]  index.html · app.js · style.css  (해시 라우팅: #/posts, #/recruits, #/chats ...)
     │  HTTP (JSON API + 정적 파일)
     ▼
 [C 서버: server]
   http.c ─ 요청 파싱 / 스레드 ─▶ api.c (api_dispatch)
                                    ├ 정지 회원 차단 (suspended_blocked)
                                    ├ route_auth       가입·로그인·세션        api.c
                                    ├ route_posts      공모전·댓글·권한        api_posts.c
                                    ├ route_admin      등록·공지 수집·통계     api_admin.c
                                    ├ route_ai         Claude 분석·추천        api_ai.c → ai.c
                                    ├ route_ml         자체 모델 추천          api_ml.c → ml.c
                                    ├ route_community  프로필·팀원 모집        api_community.c
                                    ├ route_study      스터디·멘토링           api_study.c
                                    ├ route_books      전공책 장터             api_books.c
                                    ├ route_invite     참여 권유               api_invite.c
                                    ├ route_notify     알림함                  api_notify.c
                                    ├ route_manage     관리자 회원 관리        api_manage.c
                                    └ route_chat       채팅방                  api_chat.c
   db.c (MySQL, %Q 이스케이프, 재진입 잠금)    cleanup.c (1시간마다 지난 글 정리)
   crawler.c ─ libcurl ─▶ www.skuniv.ac.kr/wp-json/wp/v2/notice
   ml.c ─ embed.c ─ libcurl ─▶ [Python 임베딩 서비스 127.0.0.1:8001]
   ai.c ─ libcurl ─▶ [Claude API]          mailer.c ─ libcurl ─▶ [SMTP (Gmail)]
     │
     ▼
 [MySQL: sku_contest]
```

- **OS 차이는 두 곳에만** 있다: `platform.c` (잠금·스레드·시간·난수·원자 연산)와 `http.c` 위쪽 (소켓). 나머지 코드에는 `#ifdef _WIN32` 가 없다.
- **선택 기능은 꺼져 있어도 나머지가 돈다**: 임베딩 서비스가 없으면 TF-IDF 만, Claude 키가 없으면 AI 메뉴를 숨긴다.
- **DB 스키마 자동 보정**: 서버가 시작할 때 없는 표·열을 스스로 만든다 (`cleanup_ensure_schema`). 기존 DB 에 SQL 을 손으로 돌리지 않아도 된다.

## 4. 주요 기능

### 4.1 회원가입 · 로그인 (학교 이메일 인증)

- 필수 항목: **학교 이메일 + 인증 코드, 학번, 이름, 전화번호, 비밀번호, 소속 학과**. 관심 키워드·자기소개는 선택.
- 인증 코드 흐름
  1. `@skuniv.ac.kr` 주소만 받는다. 이미 가입한 주소는 거절, 같은 주소로는 **60초에 한 번**.
  2. 6자리 코드를 OS 난수원으로 만들어 메일로 보내고, DB 에는 **솔트 친 해시만** 저장. **10분** 유효.
  3. **5번 틀리면** 무효, 가입에 성공하면 코드를 지운다 (1회용). API 응답에는 어떤 경우에도 코드가 실리지 않는다.
- **표시 이름은 서버가 만든다** (닉네임을 받지 않음): `손동권 + 010-9948-9687 → 손*권_9948`
  - 이름 가운데 글자를 가리고(UTF-8 글자 단위), 전화번호 가운데 묶음을 붙인다.
  - 실명·전화번호·학번은 어떤 일반 API 응답에도 나가지 않는다.
- 세션: 192비트 난수 토큰, `HttpOnly; SameSite=Lax` 쿠키, 12시간 만료.

### 4.2 공모전 게시판과 학교 공지 자동 수집

- 공지 수집: `GET https://www.skuniv.ac.kr/wp-json/wp/v2/notice?search=<검색어>&after=<2년 전>`
  - 검색어 8개(공모전·해커톤·경진대회·공모·대회·챌린지·아이디어·콘테스트), 페이지를 넘겨 2년치 전부
  - 제목 필터(`is_contest_title`): 포함어(공모전·대회·어워드·Hack 등)가 있고, 제외어(수상자·결과 발표·장학·서포터즈·교직원·채용 등)가 없는 글만
  - 본문 HTML 을 텍스트로 변환 (문단 → 줄, 목록 → `•`, 표 → `|`)
  - `ext_id` 유일 키로 **같은 공지를 두 번 올리지 않는다**
- 수집한 공모전은 바로 공개되고, 관리자가 대상 학과를 체크하면 그때부터 댓글이 그 학과로 좁혀진다.
- 매일 06:00 자동 수집 (`sku14-crawl.timer`), 관리자 화면에서 수동 수집도 가능.

### 4.3 자체 추천 모델 — 프로젝트의 핵심 기술 (`src/ml.c`, 약 2,000줄)

외부 유료 API 없이 **C 서버 안에서 학습·추론**한다. 학과별 추천, 개인 맞춤 추천, 새 글 대상 학과 예측, 팀원 매칭을 모두 이 모델이 맡는다.

| 단계 | 내용 |
| --- | --- |
| 1. 토큰화 | 낱말 + 한글 두 글자 묶음(형태소 분석기 불필요), 공지 상투어 불용어 제거, 동의어 통합(유튜브·숏폼→영상, 코딩·앱개발→개발, 인공지능→AI) |
| 2. TF-IDF | 게시물(제목 ×2 + 본문)과 학과 프로필(`dept_profiles`)을 희소 벡터로 |
| 3. Rocchio 학습 | 학과 벡터 = 프로필(α=1.0) + β(0.75) × 연결된 게시물 평균. 연결 가중치: 관리자가 체크한 글 1.0, 그 학과 학생이 댓글·♥ 한 글 0.5. 상위 40개 특징만 쓰고, 데이터가 적을수록 반영을 줄임 (`β·w/(w+1.5)`) |
| 4. 딥러닝 임베딩 | 다국어 트랜스포머로 글의 **뜻**을 384차원 벡터로. 글자가 겹치지 않아도("AI 숏폼" ↔ 미디어영상학과) 연결됨 |
| 5. 하이브리드 점수 | **최종 = 0.7 × 임베딩 + 0.3 × TF-IDF**. 트랜스포머 코사인은 무관한 글도 0.8 근처라 평균(μ) 아래는 0, 위는 0~1로 펴서 섞음 |
| 6. 확률 보정 | Platt scaling `P = 1 / (1 + e^-(a·s + b))`. 정답 쌍을 양성·나머지 학과를 음성으로 로지스틱 회귀. 데이터가 적어도 흔들리지 않게 사전값 쪽으로 당기는 MAP 추정 |
| 7. 설명 가능성 | 겹친 낱말을 **근거 키워드**로 화면에 보여 줌 |

- **자동 재학습**: "학습 데이터 서명"을 계산해 게시물·댓글·체크·프로필이 바뀌면 다음 요청 때 다시 학습 (게시물 수십 건 기준 수십 ms).
- **새 글 실시간 예측**: 관리자가 새 공모전을 쓰는 동안 `POST /api/ml/predict` 가 재학습 없이 학과별 적합 확률을 매긴다 (약 50~100ms). "30% 이상 학과 체크" 버튼으로 대상 학과를 바로 고른다.
- **개인 맞춤**: 내 학과 벡터 + 내 관심 키워드·자기소개 + 최근 ♥ 한 모집글 10개.
- **마감 반영**: 마감이 지난 공모전은 뒤로 보내고 `closed` 로 표시.
- **장애 대응**: 임베딩 서비스가 꺼져 있으면 자동으로 TF-IDF 만 쓰고, 다시 켜지면 다음 요청에서 재학습.
- **미세조정** (`ml/finetune.py`): 쌓인 정답 쌍으로 대조학습(MultipleNegativesRankingLoss). 게시물 20%를 떼어 두고 **Recall@5·MRR** 을 사전학습 모델과 비교해 **나아졌을 때만** 저장 (과적합 방지).
- 화면: 공모전 목록의 학과별 추천 탭(`#/reco/{학과}`)에서 매우 관련 70+ / 관련 50+ / 참고 25+ 로 묶어 보여 준다. 게시물 상세에는 관련 학과 상위 5개.
- 그룹 스터디·전공책 장터의 **학과별 추천** 탭도 같은 학과 벡터로 스터디(이름·소개·대상 학과)와 책(제목·과목·저자·설명·학과)을 매긴다 (`ml_rank_texts`, 재학습 없이 계산, 25점 이상).

### 4.4 Claude AI 분석 (선택)

- 게시물마다 한 번 `claude-opus-5-5` 로 요약·태그·주최·마감일·학과별 관련도(0~100)·이유를 뽑아 `post_ai` 에 저장.
- `output_config.format` 의 **JSON 스키마로 출력 형식을 강제**하고, 시스템 프롬프트(학과 목록)는 **프롬프트 캐시**로 비용을 줄인다.
- 학생 화면의 추천은 저장된 점수로만 계산하므로 **화면을 볼 때마다 API 를 부르지 않는다**. 새 글은 백그라운드에서 자동 분석.

### 4.5 내 모집 관리 · 팀원 모집글 (`#/recruits`)

- 사이드바 **내 모집 관리** (로그인 시). 탭: **내가 쓴 모집글**(팀 인원, [팀원 찾기], [모집 마감]/[다시 모집]) · **참여 중인 팀**(`#/recruits/joined`) · **모집글 둘러보기**(`#/recruits/all`, 키워드·상태 필터와 "나와 맞는 순"). 다른 사람의 모집글은 공모전 상세에서도 본다.
- 함께 나갈 공모전, 찾는 분야·역할 키워드, 인원(1~20), 마감일. 댓글로 참여 의사를 받고 작성자가 마감·삭제.
- 글쓴이가 댓글 단 회원을 **[팀원으로 받기]** 로 팀에 넣는다 (팀 채팅방은 4.10).
- 관심 키워드 41개 (관심 분야 / 맡고 싶은 역할 / 협업 성향), 가입 때 1~8개 선택.
- **"나와 맞는 순" 정렬**과 **팀원 찾기**: 회원 문서 = 키워드(가중 3) + 자기소개 + 학과, 모집글 문서 = 찾는 키워드 + 제목 + 본문.
  드문 키워드가 겹칠수록 점수가 높다(TF-IDF).
- **♥ 마음에 들어요**: 추천 모델의 학습 데이터로 쓰인다. 같은 글을 좋아한 회원(Jaccard × 0.15), 내 글을 좋아했거나 내가 좋아한 회원(+0.10)에게 가산점.

### 4.6 그룹 스터디 · 멘토링 (`#/studies`, `#/mentoring`)

- 방장이 이름·정원(스터디 2~50명, **멘토링 2~4명**)·대상 학과(선택)·소개·종료일(선택)을 정한다. 방장이 첫 멤버.
- 탭: 전체 스터디 · **내 학과 대상**(`#/studies/major`, 대상 학과 = 내 학과) · **학과별 추천**(`#/studies/reco/{학과}`, 4.3 의 모델).
- 참여·나가기, 방장의 멤버 추가(표시 이름·학과로만 검색, 학번·실명으로는 찾지 않음), 멤버별 역할(멤버 / 멘토 / 멘티).
- **정원 검사와 추가를 한 트랜잭션**으로 묶어, 두 사람이 동시에 마지막 자리에 들어와도 정원을 넘지 않는다.
- 같은 표·API 를 쓰고 `kind` 열(`study` / `mentoring`)로 구분해 코드 중복을 없앴다.

### 4.7 참여 권유와 알림함 (`#/notifications`)

- 내 모집글 / 내가 방장인 스터디·멘토링에서 **[팀원 찾기]** → 추천 모델이 고른 잘 맞는 회원 목록 (이미 함께하는 사람은 제외).
- **[✉ 참여 권유]** → 상대의 알림함 + 학교 메일로 안내
  - 같은 모임에서 같은 회원에게는 **한 번만** (DB 유일 키), 한 사람이 **하루 30건**까지, 받는 사람의 메일 주소는 화면에 나오지 않음
- 알림함: 상단바 🔔 로 연다(사이드바 메뉴 없음). 안 읽은 수 배지(1분마다 갱신), 종류(참여 권유 ✉ / 수락 ✅ / 관리자 알림 📢 / 정지 ⛔ / 정지 해제 🔓 / 팀원 수락 🤝)
  - 권유 알림의 **[참여하기]**: 스터디·멘토링은 바로 멤버로, 모집글은 참여 댓글 자동 작성 + **팀원으로 등록**. 권유한 사람에게 수락 알림
  - 90일 뒤 자동 삭제

### 4.8 전공책 장터 (`#/books`)

- 제목·저자·과목·학과·가격(0원 = 나눔)·책 상태(새 책 / 깨끗함 / 필기 조금 / 필기 많음)·설명, **사진 최대 5장**(카메라·앨범).
- 브라우저에서 긴 변 1280px JPEG 로 줄여 올린다 (수 MB → 수십~수백 KB). 서버는 **JPG·PNG·WEBP 만, 파일 첫 바이트(서명)까지 확인**, 한 장 1MB 제한.
- 검색(제목·저자·과목), 학과, 판매 상태, 최신순·가격순. 판매 중 → 예약 중 → 판매 완료, 판매 완료 30일 뒤 자동 삭제.
- 탭: 전체 책 · **내 학과 대상**(`#/books/major`, 판매 글의 학과 = 내 학과) · **학과별 추천**(`#/books/reco/{학과}`, 판매 중인 책만, 4.3 의 모델).
- 문의 댓글에서 판매자 댓글은 **판매자** 팻말로 구분.

### 4.9 관리자 기능 (`#/admin`, `#/admin/users`, `#/admin/content`)

- 운영: 공모전 직접 등록(실시간 학과 예측), 공지 수집·게시·숨기기, 대상 학과 체크, AI 분석 진행 상황, 통계.
- 회원 관리: 학번·실명·학과·이메일·글 수 조회·검색(관리자에게만), 회원 추가(인증 없이), 삭제(그 회원의 글·댓글 함께), **정지**(1~365일, 사유).
  - 정지된 회원은 **보기만** 가능. 글·댓글·참여·권유·판매는 **API 입구 한 곳**(`suspended_blocked`)에서 막아 기능마다 검사를 빠뜨릴 일이 없다.
  - 기간이 지나면 자동 해제, [정지 풀기]로 즉시 해제.
- 📢 알림 보내기, 전체 게시물(모집·스터디·멘토링·전공책)을 한곳에서 보고 주인에게 알림.

### 4.10 채팅방과 모집글 팀 (`#/chats`, `src/api_chat.c`)

팀원 모집 팀, 그룹 스터디, 멘토링에 들어간 사람끼리 **채팅방**에서 이야기한다. 모임에 들어가면 그 모임의 방에 바로 들어갈 수 있고, 방을 따로 만들 필요는 없다.

| 방 | 멤버 |
| --- | --- |
| 그룹 스터디 · 멘토링 | 그 모임의 멤버 (`study_members`) |
| 팀원 모집 | 글쓴이 + 글쓴이가 받은 팀원 (`recruit_members`, 새 표) |

- **모집글 팀**: 전에는 모집글에 멤버가 없어(참여 = 댓글) 방을 붙일 수 없었다. 그래서 팀 개념을 새로 만들었다.
  - 상세 화면의 **팀** 칸에 글쓴이 + 팀원. 글쓴이(·관리자)는 댓글 작성자를 **[팀원으로 받기]**, 팀원을 [내보내기], 팀원은 [팀 나가기]. 팀원은 20명까지
  - 받은 회원에게 🤝 알림 → 누르면 팀 채팅방으로. 목록 "상태"에 **내가 속한 팀** 보기 (마감한 글 포함)
- **채팅방 화면**: 사이드바 **채팅방** 메뉴와 안 읽은 메시지 배지, 최근 대화가 있는 방이 위로. 말풍선, 날짜 구분선, Enter 보내기 · Shift+Enter 줄바꿈(한글 조합 중 Enter 는 보내지 않음), 내 메시지 삭제, 이전 대화 더 보기.
  모집글 카드·상세, 스터디·멘토링 목록·상세에 **채팅방으로 이동** 버튼.
- **권한**: 멤버가 아니면 관리자라도 들어갈 수 없고, 나가거나 내보내지면 바로 못 들어간다. 정지된 회원은 읽기만 가능 (기존 정지 차단이 그대로 적용).
- **동작 방식**: 웹소켓 대신 채팅방 화면이 **3초마다** 새 메시지만 받아 간다(`?after=마지막id`). 탭이 가려져 있으면 쉬고, 다른 화면으로 가면 멈춘다.
  안 읽은 수는 방마다 "어디까지 읽었는지"(`chat_reads`)를 저장해 그보다 새로운 남의 메시지를 센다.
- **남용 방지**: 메시지 1000자까지, 1분에 30개까지.

| 메서드 | 주소 | 설명 |
| --- | --- | --- |
| GET | `/api/chats` | 내 채팅방 목록 + 마지막 메시지 · 안 읽은 수 |
| GET | `/api/chats/{recruit\|study}/{id}` | 방 정보·멤버 + 최근 100개 (`?after=` 새 메시지, `?before=` 이전 대화) |
| POST | `/api/chats/{recruit\|study}/{id}/messages` | 보내기 |
| DELETE | `/api/chat-messages/{id}` | 내 메시지 지우기 |
| POST / DELETE | `/api/recruits/{id}/members[/{uid}]` | 팀원으로 받기 / 내보내기·팀 나가기 |

### 4.11 지난 글 자동 정리 (`src/cleanup.c`)

서버가 켜질 때 한 번, 이후 **1시간마다** 백그라운드 스레드가 정리한다. 마감일 **당일까지는 남는다**.

| 대상 | 지우는 때 |
| --- | --- |
| 공모전 | 마감일이 지나면 (댓글·대상 학과·AI 분석은 CASCADE) |
| 마감일을 모르는 학교 공지 | 게시일로부터 60일 뒤 (`cleanup.no_deadline_days`) |
| 팀원 모집 | 마감했거나 마감일이 지나면. 단 **팀원이 있는 글은 쓴 날부터 90일까지** 남김 (팀 채팅방 때문에) |
| 스터디·멘토링 | 종료일이 지나면 (종료일이 없으면 남김) |
| 판매 완료한 전공책 | 30일 뒤 |
| 알림 | 90일 뒤 |
| 채팅 메시지·읽음 기록 | 방(모집글·스터디)이 지워지면 |

- 지운 공모전의 공지 기록은 남겨 **다음 수집 때 다시 올라오지 않는다**. 공모전이 지워져도 연결된 모집글은 남는다(`post_id = NULL`).
- **공지 본문에서 마감일 추출** (`notice_guess_deadline`): 수집한 공지는 마감일이 모두 비어 있었다.
  "접수·응모 기간" → "신청·제출·마감" → "기간·일정" 순으로 우선순위를 두고, 그 뒤 날짜 중 **가장 늦은 날**을 고른다.
  `2026. 09. 28. ~ 2026. 10. 22.`, `9.28.(월)~10.31.(토)`, `26년 6월 1일`, `’26. 03. 26.` 등 다양한 표기와 연도 넘김, 전화번호 오인 방지까지 처리.

## 6. 보안 설계

| 위협 | 대응 |
| --- | --- |

## 7. 배포와 운영

### 7.1 실행 환경 전환: Windows → 리눅스

처음에는 Windows 전용이었으나, Windows Smart App Control 이 서명되지 않은 exe 를 모두 막아 개발 PC 에서 실행이 불가능했다.
그래서 **같은 소스로 리눅스·맥에서도 빌드·실행**되게 바꾸고 리눅스 노트북을 상시 서버로 쓰기로 했다.

| 영역 | 전 | 후 |
| --- | --- | --- |
| 소켓 | Winsock2 | Winsock2 / BSD 소켓 (`#ifdef` 는 `http.c` 위쪽에만) |
| 바깥 HTTPS | WinHTTP (3곳에 중복 구현) | **libcurl 하나** (`net.c`) |
| 잠금·스레드·시간·난수 | Win32 API | `platform.c` 추상화 (재진입 pthread 뮤텍스, 2MB 스레드 스택 등) |
| 실행 스크립트 | `.bat`, `.ps1` | bash `.sh` |
| 상시 운영 | 없음 | systemd 서비스 |

### 7.2 원클릭 공개 (`./서버공개하기.sh`)

1. 패키지 설치 → 빌드 → DB 생성 → 전용 DB 계정(`sku`, 32자 난수 비밀번호) (`setup-linux.sh`)
2. 관리자 계정 생성
3. systemd 서비스 등록: 부팅 시 자동 시작, 죽으면 5초 뒤 재시작, 80 포트 권한만 부여(root 로 돌지 않음), 노트북 절전 방지
4. 게시물이 0건이면 학교 공지를 바로 수집
5. **Tailscale Funnel** 로 고정 HTTPS 공개 주소 발급 (`https://<컴퓨터이름>.<tailnet>.ts.net`)

몇 번을 다시 돌려도 이미 된 단계는 건너뛴다. Funnel 을 고른 이유: 접속하는 사람은 아무것도 깔 필요가 없고, 도메인을 사지 않아도 **고정 주소 + HTTPS** 가 붙으며 집 IP 가 드러나지 않는다.

### 7.3 운영 명령

```sh
systemctl status sku14                 # 상태
journalctl -u sku14 -f                 # 로그
make && sudo systemctl restart sku14   # 코드 반영
scripts/run-server.sh --crawl          # 공지 수집
scripts/run-server.sh --cleanup        # 지난 글 정리
scripts/run-server.sh --test-mail 주소  # 메일 설정 시험
```

### 개발 중 발견하고 고친 주요 문제

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 서로 다른 사용자가 같은 솔트를 받고 세션 토큰이 충돌 | Windows UCRT 의 `rand()` 상태가 스레드마다 따로라 모든 스레드가 같은 값 | OS 난수원(`rand_s`, `/dev/urandom`)으로 교체 |
| localhost 에서 로그인이 풀림 | Cookie 헤더 버퍼 1024바이트, 다른 쿠키가 많으면 `sid` 가 잘림 | 8192바이트로 확대 |
| 서버를 열었는데 공모전이 하나도 안 보임 | 수집 타이머가 매일 06:00 에만 돌아 첫 수집이 다음 날 | 설치 직후 게시물 0건이면 바로 수집 |
| 리눅스에서 서버가 통째로 죽음 | 브라우저가 먼저 끊은 소켓에 `send` → SIGPIPE | SIGPIPE 무시 |
| 일부 환경에서 버튼이 반응 없음 | 브라우저 기본 `confirm()` 이 막힘 | 사이트 안 확인 창(`askConfirm`)으로 12곳 교체 |
| 리눅스에서 DB 접속 불가 | Ubuntu MySQL root 는 OS 계정 인증(`sudo mysql`) | 전용 계정 + 유닉스 소켓 접속 |
| VSCode 터미널에서 sudo 실패 | snap 판 VSCode 의 no-new-privileges | 스크립트가 감지해 일반 터미널을 안내 |

## 11. 정리

- **과제 핵심 요구사항**(대상 학과만 댓글, 열람은 누구나)을 서버 한 곳(`can_comment`)에서 판정해 우회할 수 없게 구현했다.
- 프레임워크 없이 **C 로 HTTP 서버·JSON·SHA-256 까지 직접 구현**하고, Windows·리눅스·맥에서 같은 소스로 빌드되게 만들었다.
- 학교 공지를 **자동 수집**하고, 외부 API 없이 **TF-IDF + Rocchio + 딥러닝 임베딩 + 확률 보정**으로 학과·개인 맞춤 추천을 하는 **자체 추천 모델**을 만들었다.
- 공모전 정보에서 끝나지 않고 **팀원 모집 → 팀원 찾기 → 참여 권유 → 알림 → 참여 → 팀 채팅방**까지 이어지는 흐름과 스터디·멘토링·전공책 장터로 커뮤니티를 완성했다.
- 리눅스 노트북에서 **systemd + Tailscale Funnel** 로 실제로 공개 운영했고, 지난 글 자동 정리와 관리자 정지 기능으로 운영 부담을 줄였다.
