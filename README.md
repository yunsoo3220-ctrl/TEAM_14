# 전공책 장터 · 참여 권유 · 알림함 · 관리자 기능 (변경 정리, 2026-10-13)

학생끼리 **전공책을 사고팔고**, 모집글·스터디의 주인이 **잘 맞는 회원에게 참여를 권유**하고,
모든 회원이 **알림함**으로 소식을 받게 했다. 관리자는 **회원 관리 · 정지 · 알림 보내기 · 전체 게시물 보기**를 할 수 있다.

| 한 일 | 핵심 |
| --- | --- |
| 1. 전공책 장터 | 사진(카메라·앨범, 최대 5장)과 함께 판매 글. 검색·학과·가격순, 문의 댓글, 판매자 댓글 표시 |
| 2. 팀원 찾기 → 참여 권유 | 메뉴의 팀원 찾기를 없애고 모집글·스터디·멘토링 안에 [팀원 찾기]. 권유는 한 사람에게 한 번 |
| 3. 알림함 | 🔔 배지, 알림 목록·자세히 보기. 권유 알림에서 바로 [참여하기] |
| 4. 관리자 | 회원 보기·추가·삭제·정지(기간·사유), 알림 보내기, 전체 게시물과 주인에게 알림 |
| 5. 화면 손질 | 확인 창을 사이트 안에서 직접 그림, 본문을 화면 폭에 맞춰 가운데 정렬 |

---

## 1. 전공책 장터 (`#/books`)

- **판매 글**: 제목, 저자·출판사, 과목명, 학과, 가격(0원 = 나눔), 책 상태(새 책 / 깨끗함 / 필기 조금 / 필기 많음), 설명
- **사진**: [📷 카메라로 찍기] · [🖼 앨범에서 고르기], 최대 5장, 첫 장이 대표 사진
  - 브라우저에서 긴 변 1280px JPEG 로 줄여 올린다 (휴대폰 사진 몇 MB → 수십~수백 KB)
  - 서버는 JPG·PNG·WEBP 만 받고 파일 첫 바이트(서명)까지 확인한다. 사진은 DB(`book_photos`)에 저장
- **목록**: 검색(제목·저자·과목), 학과, 판매 중 / 판매 완료 포함 / 내 판매 글, 최신순·가격순
- **판매자**: 판매 중 → 예약 중 → 판매 완료, 삭제. 판매 완료 30일 뒤 자동 삭제
- **문의 댓글**: 판매자가 쓴 댓글은 이름이 파랗게, 옆에 **판매자** 팻말

## 2. 팀원 찾기 · 참여 권유

- 사이드바의 "팀원 찾기" 메뉴를 없앴다. 대신 **내 모집글 / 내가 방장인 스터디·멘토링** 상세 화면에 [팀원 찾기] 버튼
- 나와 잘 맞는 회원 목록(기존 추천 모델)이 나오고, 이미 함께하는 사람은 빠진다
- 프로필 카드의 **[✉ 참여 권유]** → 그 회원의 **알림함 + 학교 메일**로 안내
  - 같은 모임에서 같은 회원에게는 **한 번만** (DB 유일 키로 막음, 새로고침해도 "✓ 권유 보냄")
  - 받는 사람의 메일 주소는 화면에 나오지 않는다. 한 사람이 하루 30건까지
  - 메일 링크 주소는 Tailscale Funnel 공개 주소를 자동으로 쓴다 (`smtp.env` 의 `SKU_SITE_URL` 로 고정 가능)

## 3. 알림함 (`#/notifications`)

- 로그인하면 사이드바 **알림함**과 상단 **🔔**, 안 읽은 수 배지 (화면 이동 때와 1분마다 갱신)
- 알림 종류: 참여 권유 ✉, 권유 수락 ✅, 관리자 알림 📢, 계정 정지 ⛔, 정지 해제 🔓
- 참여 권유 알림의 **[참여하기]**
  - 스터디·멘토링 → 바로 멤버로 가입
  - 팀원 모집 → 모집글에 참여 댓글 자동 작성 (모집글에는 멤버 개념이 없으므로)
  - 권유한 사람에게 "수락했습니다" 알림. 한 번만 누를 수 있다
- 관리자·정지 알림은 눌러서 **자세히 보기**, 관련 글이 있으면 [관련 화면으로 가기]
- 모두 읽음 · 삭제, 90일 뒤 자동 삭제

## 4. 관리자 기능 (관리자 메뉴 → 운영 / 회원 관리 / 전체 게시물 탭)

- **관리자 계정**: 학번 `20250001`, 이름·표시 이름 "관리자" (비밀번호는 팀에 따로 공유)
- **회원 관리** (`#/admin/users`)
  - 모든 회원의 학번·실명·학과·이메일·글 수 보기, 검색 (실명·학번은 관리자에게만 보인다)
  - **회원 추가**: 이메일 인증 없이 바로 로그인 가능한 계정
  - **삭제**: 그 회원의 모집글·스터디·전공책·댓글·알림도 함께 삭제. 관리자 계정은 못 지움
  - **정지**: 기간(1~365일)과 사유 → 회원 알림함으로 "N일 정지, 사유" 통보. **[정지 풀기]** 로 바로 해제, 기간이 지나면 자동 해제
    - 정지된 회원은 **보기만** 가능. 글·댓글·참여·권유·판매 글은 서버 입구에서 한 번에 막는다 (`src/api.c` 의 `suspended_blocked`)
    - 정지된 회원 화면 위에 기간·사유 안내 띠
  - **📢 알림 보내기**: 회원 알림함으로 제목·내용
- **전체 게시물** (`#/admin/content`): 팀원 모집·그룹 스터디·멘토링·전공책을 한곳에서, 주인(작성자·방장·판매자)과 상태 표시
  - **📢 방장에게 알림**: 받은 사람이 누르면 그 글로 바로 이동

## 5. 화면 손질

- 브라우저 기본 확인 창(`confirm`)이 막힌 환경에서는 버튼이 아무 반응이 없었다 → **사이트 안 확인 창**(`askConfirm`)으로 12곳 모두 교체
- 정지 입력은 오류를 빨간 글씨로 보여 주고, 버튼을 한 번 더 눌러 확정
- 본문이 왼쪽으로 쏠리던 것 → 화면 폭에 따라 늘었다 줄며 **가운데 정렬** (최대 1320px, 아주 넓은 화면 1560px)

| 새 서버 모듈 | `src/api_books.c` (장터), `src/api_invite.c` (권유·수락), `src/api_notify.c` (알림함), `src/api_manage.c` (관리자) |
| 서버 수정 | `src/api.c` (라우터, 정지 차단, 관리자 회원 추가, 메일 링크 주소), `src/api.h`, `src/api_community.c`, `src/api_study.c`, `src/cleanup.c/.h`, `src/http.c/.h` (본문 한도 8MB, X-Forwarded-Proto) |

| 화면 | `www/index.html`, `www/app.js`, `www/style.css` |
| 스크립트 | `scripts/run-server.sh` (Funnel 주소 자동 감지), `scripts/env.sh`, `smtp.env.example` |
