## 1. 그룹 스터디

### 1.1 대상 학과 여러 개 + 대상 학과만 참여

- 만들기·수정 화면의 대상 학과가 **학과 체크박스**로 바뀌었다 (기본은 내 학과 체크, 모두 풀면 학과 무관).
- 새 표 `study_departments (group_id, department_id)`. 예전 `study_groups.department_id`(학과 하나)는 옮겨 담고 더는 쓰지 않는다.
- **대상 학과가 아니면 멤버가 될 수 없다.** 검사는 `study_department_ok()` 한 곳에 있고, 멤버가 되는 모든 길
  (참여 신청 수락 · 방장의 직접 추가 · 참여 권유 수락)이 거치는 `study_add_member()` 가 부른다.
  방장의 멤버 검색과 "팀원 찾기" 추천에서도 대상이 아닌 회원은 빠진다.
- 멤버 검색에서 검색어를 비우고 [찾기]를 누르면 추가할 수 있는 회원을 모두 보여 준다 (전에는 아무 일도 없었다).

### 1.2 정원 최대 8명 · 수정

- 정원 2~8명. 8명보다 컸던 스터디는 서버 시작 때 8명으로 줄였다 (이미 더 모였으면 지금 인원까지만).
- 방장·관리자는 [수정] 으로 이름·정원·대상 학과·종료일·소개를 고친다 (`PUT /api/studies/{id}`).
  정원은 지금 인원보다 적게 줄일 수 없고, 대상 학과를 바꿔도 이미 들어온 멤버는 그대로 둔다.

### 1.3 참여 신청 → 방장 수락 → 확정

**문제** — [참여하기] 를 누르면 바로 들어가고 바로 나갈 수 있어, 멤버가 너무 자주 바뀌었다.

**해결**

```
[참여 신청] ──▶ 방장 알림함 ──▶ 방장 [수락] ──▶ 멤버
                               └ [거절] ──▶ 신청한 사람에게 알림
멤버 수 = 정원 ──▶ 확정된 그룹 (멤버 고정)
```

- 신청은 `study_requests (group_id, user_id)` 에 남는다. 신청한 사람은 [신청 취소] 할 수 있다.
- 방장은 스터디 화면의 **참여 신청 (N)** 칸에서 [수락] / [거절].
- 마지막 자리가 차면 `study_groups.confirmed_at` 을 채워 **확정된 그룹**이 된다.
  - 멤버 모두에게 확정 알림, 남아 있던 신청은 지우고 신청한 사람에게 마감 알림.
  - 그 뒤로는 신청 · 추가 · 나가기 · 내보내기 · 정원 변경을 막는다 (관리자만 내보낼 수 있다).
  - 방장의 직접 추가나 참여 권유 수락으로 마지막 자리가 차도 똑같이 확정된다 (판정이 `study_add_member()` 안에 있어서).
- 확정된 그룹은 전체·내 학과 대상·학과별 추천 목록에서 빠지고 **확정된 그룹** 탭(`#/studies/confirmed`)에만 보인다.
  멤버가 자기 그룹을 찾을 수 있게 "내가 속한 스터디" 와 내 모집 관리에는 계속 보인다.

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| POST / DELETE | `/api/studies/{id}/join` | 참여 신청 / 신청 취소 |
| POST / DELETE | `/api/studies/{id}/requests/{uid}` | 신청 수락 / 거절 (방장·관리자) |
| PUT | `/api/studies/{id}` | 스터디 수정 |
| GET | `/api/studies?confirmed=1` | 확정된 그룹만 (기본 목록은 확정된 그룹을 뺀다) |

## 2. 팀원 모집글과 메뉴

- **공모전 모집** (`#/recruits/all`): "모집글 둘러보기" 를 내 모집 관리의 탭에서 빼서 사이드바 "공모전 목록" 바로 아래 메뉴로 옮겼다.
  로그인하지 않아도 보이고, **내가 쓴 글은 빼고** 보여 준다.
- **내 모집 관리** (`#/recruits`): 탭은 내가 쓴 모집글 / 참여 중인 팀. 모집글과 함께 **내가 방장인 스터디**·**참여 중인 스터디**도 보여 준다.
  카드마다 [수정] [삭제] (모집글), [팀원 찾기] [멤버 관리] [수정] [삭제] (스터디).
- **모집글 수정** (`PUT /api/recruits/{id}`, `#/recruits/{id}/edit`): 쓰기와 같은 함수(`handle_recruit_save`)로 같은 검사를 한다.
- **대상 학과 제한**: 대상 학과가 정해진 공모전이면 그 학과 학생만 그 공모전으로 모집글을 쓸 수 있다.
  그 공모전 상세에서 글쓰기 주소로 바로 들어와도 안내만 보여 준다.
- **지난 마감일 금지**: 달력에서 오늘 이전 날짜를 고를 수 없고 서버도 거절한다. 고칠 때 원래 마감일을 그대로 두는 것은 된다.
- **한 글자 내용 오류**: 내용 길이를 바이트로 세서 한글 한 글자(3바이트)가 "5 미만" 으로 거절됐다. 글자 수로 세고, 비어 있지만 않으면 받는다.
- 내가 쓴 모집글에는 "나와 맞는 정도" 퍼센트를 보이지 않는다.

## 4. 회원

- **회원 정보 수정** (내 프로필 · 자기소개 아래): 이름 · 전화번호 · 소속 학과. 학번과 학교 이메일은 바꿀 수 없다.
- **비밀번호 변경**: 새 비밀번호 8자 이상, 지금 것과 달라야 한다. 바꾸면 지금 기기를 뺀 다른 기기의 로그인은 끊는다.
  정지된 계정도 비밀번호는 바꿀 수 있다 (보안 조치).
- 둘 다 **현재 비밀번호**를 다시 넣어야 저장된다 (`PUT /api/account`, `PUT /api/account/password`).
- **표시 이름**: `이름 가운데 * + "_" + 학번 앞에서 셋째·넷째 숫자`

  ```
  손동권 + 학번 20241234  ->  손*권_24
  ```

  예전 규칙(`손*권_9948`, 전화번호 가운데 묶음)으로 만든 이름은 서버 시작 때 새 규칙으로 바꾼다 (`display_name_for`).
  관리자는 이름 그대로.

## 5. 전공책 장터

- **내 판매 글** 탭 (`#/books/mine`): 내가 올린 글만, 판매 완료 포함. 판매 상태 필터에 숨어 있던 같은 선택지는 뺐다.
- **거래 장소**: 유담관 · 북악관 · 본관 · 한림관 · 혜인관 · 문예관 · 대일관 · 청운관 · 은주1관 · 은주2관 (목록에 없으면 직접 입력).
- **가격**: 500원 단위 · 100만 원 상한을 없앴다. 그 뒤 42억 원이 넘는 값을 넣으면 DB 열(`INT UNSIGNED`)이 넘쳐 저장이 안 되어
  `BIGINT UNSIGNED` 로 넓혔다. 서버는 범위를 먼저 확인한 뒤 정수로 바꾸고(`read_price`, C 의 실수→정수 오버플로 방지),
  0 ~ 9,007,199,254,740,991원(브라우저가 정확히 다루는 가장 큰 정수)을 받는다.
- **희망 거래 시각**: 10분 단위 → 1분 단위.
