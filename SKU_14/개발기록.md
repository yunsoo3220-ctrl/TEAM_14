## 1. Windows → 리눅스·맥 이식

**문제** — 서버가 Windows 전용이었는데 Smart App Control 이 서명 없는 exe 를 모두 막아 개발 PC 에서 실행조차 안 됐다.
상시 서버로 쓸 리눅스 노트북에서 돌려야 했다.

**해결** — 같은 소스 하나로 Windows·리눅스·macOS 를 모두 빌드하게 바꿨다.

| 영역 | 전 | 후 |
| --- | --- | --- |
| 소켓 | Winsock2 | Winsock2 / BSD 소켓 (`http.c` 위쪽에서만 분기) |
| 바깥 HTTPS | WinHTTP, 3개 파일에 같은 코드 복사 | **libcurl 하나** (`net.c`) |
| 잠금·스레드·시간·난수·원자 연산 | Win32 API 직접 호출 | `platform.c` 추상화 층 |
| 실행 스크립트 | `.bat`, `.ps1` | bash `.sh` |
| 상시 운영 | 없음 | systemd 서비스 |

**기술 포인트**
- **OS 차이는 두 곳에만**: `platform.c` 와 `http.c` 위쪽. 나머지 코드에는 `#ifdef _WIN32` 가 하나도 없다.
- **재진입 뮤텍스**: `db_lock()` 을 잡은 채 `db_exec()` 를 부르는 코드가 있어 POSIX 쪽도 `PTHREAD_MUTEX_RECURSIVE` 로 Windows `CRITICAL_SECTION` 과 같은 성질을 맞췄다.
- **스레드 스택 2MB 고정**: macOS 보조 스레드 기본값(512KB)이 Windows(1MB)보다 작아서.
- **SIGPIPE 무시**: 리눅스에서는 브라우저가 먼저 끊은 소켓에 `send` 하면 프로세스가 통째로 죽었다.
- **DB 접속**: Ubuntu MySQL root 는 OS 계정 인증이라 서버가 접속할 수 없다. 전용 계정(`sku`, 32자 난수 비밀번호)을 만들고, MySQL 8 의 TLS 요구를 피하려고 유닉스 소켓으로 접속.

**결과** — Windows(`-Wall -Wextra` 경고 없음)와 리눅스 노트북에서 빌드·실행. Windows 전용 실행 스크립트(`.bat`·`.ps1`)는 bash 스크립트로 대신하고 지웠다.

## 2. 원클릭 서버 공개 (`서버공개하기.sh`)

**문제** — 설치·빌드·DB·서비스 등록·외부 공개를 사람이 순서대로 해야 했고, 다시 할 때마다 실수가 났다.

**해결** — 스크립트 하나로 끝까지 진행하고, 이미 된 단계는 건너뛴다(몇 번을 다시 돌려도 안전).

1. 패키지 설치 → 빌드 → DB 생성 → 전용 DB 계정
2. 관리자 계정 생성
3. systemd 서비스 등록: 부팅 시 자동 시작, 죽으면 5초 뒤 재시작, 80 포트 권한(`CAP_NET_BIND_SERVICE`)만 주고 root 로 돌지 않음, 노트북 절전 방지
4. 게시물이 0건이면 학교 공지를 바로 수집
5. Tailscale Funnel 로 고정 HTTPS 주소 발급

**공개 방식 비교 후 선택**

| 방법 | 접속자 준비 | 주소 |
| --- | --- | --- |
| **Tailscale Funnel (선택)** | 없음 | 고정 HTTPS, 재부팅해도 유지 |
| 일반 Tailscale | 각자 설치·초대 | `http://100.x.x.x` |
| Cloudflare 임시 터널 | 없음 | 켤 때마다 바뀜 |
| 공유기 포트 포워딩 | 없음 | 집 IP 노출, HTTPS 없음 |

**운영하며 고친 문제**
- 서버를 열었는데 공모전이 0건 → 수집 타이머가 매일 06:00 에만 돌아 첫 수집이 다음 날이었다. 설치 직후 0건이면 바로 수집하게 했다.
- VSCode 터미널에서 sudo 실패 → snap 판 VSCode 의 "no new privileges" 때문. 스크립트가 감지해 일반 터미널을 안내한다.

**보안 점검** — `smtp.env` 가 git 기록에 없음을 확인, 웹 경로 우회(`/../smtp.env`, `/%2e%2e/smtp.env` 등) 5가지 모두 400/404, 파일 권한 664 → 600.

## 3. 지난 글 자동 정리와 마감일 추출

**문제** — 마감이 지난 공모전·모집글이 계속 쌓였다. 게다가 수집한 학교 공지 136건은 **마감일이 전부 비어 있어** 기준으로 삼을 것도 없었다.

**해결**
- 서버 안 백그라운드 스레드가 시작할 때 한 번, 이후 **1시간마다** 정리한다 (systemd 가 없는 Windows 에서도 동작). 마감일 당일까지는 남긴다.
- 공지 본문에서 마감일을 뽑는 `notice_guess_deadline()` 을 만들었다.
  1. "접수·응모 기간" → "신청·제출·마감" → "기간·일정" 순으로 줄을 찾는다 ("결과보고서 제출" 같은 뒷일정을 피하려고 우선순위를 둠)
  2. 그 뒤 날짜 중 **가장 늦은 날**(기간의 끝)을 고른다
  3. 게시일과 동떨어진 날(행사 연혁 등)은 버린다

| 원문 표기 | 결과 |
| --- | --- |
| `2026. 09. 28. ~ 2026. 10. 22.` | 2026-10-22 |
| `9.28.(월)~10.31.(토)` | 2026-10-31 (뒤 날짜는 앞 연도를 따름) |
| `26년 6월 1일 ~ 10월 2일` | 2026-10-02 (두 자리 연도) |
| `’26. 03. 26. ~ 06. 21.` | 2026-06-21 |
| 12월 공지의 `1.10. 까지` | 이듬해 1월 10일 |
| `02-940-7114` | 날짜로 보지 않음 (전화번호) |

- 쓰던 DB 에 SQL 을 손으로 돌리지 않도록, 서버가 시작할 때 없는 표·열을 스스로 만든다 (`cleanup_ensure_schema`, MySQL 8 에 없는 `ADD COLUMN IF NOT EXISTS` 대신 `information_schema` 확인).

**결과** — 136건 중 **124건(91%)** 에서 마감일을 찾았다. 처음 틀린 4건은 원문과 대조해 규칙을 고쳤고, 틀리더라도 늦게 잡는 쪽(글이 오래 남음)으로 설계했다.
실제 반영 때 미리 계산한 그대로 "공모전 127건 삭제", 9건(마감 전 7 + 마감일 모르는 최근 공지 2)이 남았다.

## 4. 커뮤니티 확장 — 전공책 장터 · 참여 권유 · 알림함

**문제** — 공모전 정보와 모집글만으로는 학생들이 계속 들어올 이유가 약했고, 모집글을 써도 맞는 사람에게 닿지 않았다.

**해결**
- **전공책 장터**: 사진 최대 5장(카메라·앨범). 브라우저에서 긴 변 1280px JPEG 로 줄여 올리고(수 MB → 수십~수백 KB), 서버는 확장자가 아니라 **파일 첫 바이트(매직 바이트)** 로 JPG·PNG·WEBP 인지 확인한다. 판매 중 → 예약 중 → 판매 완료, 판매자 댓글 팻말.
- **참여 권유**: 메뉴의 "팀원 찾기"를 모집글·스터디 상세 안으로 옮겼다. 추천 모델이 고른 회원에게 [✉ 참여 권유] → 알림함 + 학교 메일. 같은 모임·같은 회원에게 한 번만(DB 유일 키), 하루 30건, 받는 사람 메일 주소는 비공개.
- **알림함**: 🔔 안 읽은 수 배지, 권유 알림에서 바로 [참여하기], 90일 뒤 자동 삭제.

## 5. 관리자 회원 관리 · 정지

**해결**
- 회원 조회·검색(실명·학번은 관리자에게만), 인증 없이 회원 추가, 삭제(글·댓글 함께), 정지(1~365일, 사유 → 알림 통보), 📢 공지 알림, 전체 게시물 보기.
- **정지 검사를 API 입구 한 곳**(`suspended_blocked`)에 두었다. 기능마다 검사를 넣으면 새 기능을 만들 때 빠뜨리기 쉬워서, 글·댓글·참여·권유·판매·채팅을 라우터 앞에서 한 번에 막는다. 정지된 회원은 보기만 가능.

**함께 고친 문제** — 일부 환경에서 버튼이 반응하지 않았다. 브라우저 기본 `confirm()` 이 막힌 것이 원인이라 사이트 안 확인 창(`askConfirm`)으로 12곳을 교체했다.

## 6. 채팅방과 모집글 팀

**문제** — 팀이 모여도 연락은 카카오톡 등 바깥에서 해야 했다. 게다가 모집글에는 "멤버" 개념이 없어(참여 = 댓글) 방을 붙일 수도 없었다.

**해결**
- 모집글에 **팀** 개념을 새로 만들었다 (`recruit_members`). 글쓴이가 댓글 단 회원을 [팀원으로 받기], 내보내기·팀 나가기, 최대 20명. 참여 권유를 수락하면 팀원이 된다.
- 모집글 팀·그룹 스터디마다 **멤버끼리만 들어가는 채팅방**을 자동으로 붙였다. 따로 방을 만들 필요가 없다.
- 말풍선, 날짜 구분선, Enter 보내기 · Shift+Enter 줄바꿈, 이전 대화 더 보기, 안 읽은 메시지 배지.

**기술 포인트**
- **폴링으로 단순하게**: 웹소켓 대신 3초마다 `?after=마지막id` 로 새 메시지만 받는다. 탭이 가려지면 쉬고 화면을 떠나면 멈춘다. 연결당 스레드인 지금 서버 구조에서 연결을 붙잡아 두지 않으려는 선택.
- **안 읽은 수**: 방마다 마지막으로 읽은 id(`chat_reads`)만 저장하고 그보다 새로운 남의 메시지를 센다.
- **방이 두 종류**(모집글·스터디)라 외래 키를 걸 수 없어, 방이 지워진 메시지는 자동 정리가 지운다.
- **한글 입력**: 조합 중 Enter(글자 확정)는 보내지 않는다.
- 팀원이 있는 모집글은 마감해도 쓴 날부터 90일까지 남긴다 (채팅방 보존).
- 멤버가 아니면 관리자도 못 들어간다. 1000자, 1분 30개 제한.

## 7. 메뉴 정리와 학과 탭 — 서경스터디

**문제** — 기능이 늘며 사이드바가 9개 메뉴로 길어졌고, 멘토링은 스터디와 거의 같은 기능이 따로 있었다.

**해결**
- **멘토링을 스터디로 합침**: 별도 메뉴를 없애고 스터디의 멘토·멘티 역할로 대신했다. 남아 있던 멘토링은 서버 시작 때 멤버·역할·채팅을 그대로 둔 채 스터디로 옮기고, 예전 알림·메일의 `#/mentoring/{id}` 주소는 `#/studies/{id}` 로 넘긴다.
- **사이드바 9개 → 5개**: 공모전 목록 · 그룹 스터디 · 전공책 장터 · 내 모집 관리 · 채팅방. 알림함·프로필은 상단바로.
- **화면마다 학과 탭**: 공모전 · 스터디 · 전공책에 **전체 / 내 학과 대상 / 학과별 추천**. 스터디에는 학과가 없어서 **대상 학과** 열을 새로 만들고, 기존 스터디는 방장의 학과로 채웠다.
- **추천 모델 재사용**: 공모전용 학과 벡터로 스터디·책도 매기는 `ml_rank_texts` 를 추가했다. 스터디·책은 학습 대상이 아니므로 **재학습 없이** 글마다 벡터를 만들어 비교하고, 임베딩은 한 번에 묶어 요청한다.
- **내 모집 관리**: 내가 쓴 모집글 / 참여 중인 팀 / 모집글 둘러보기 탭.
- 서비스 이름을 **서경스터디**로 바꿨다. 한글 보낸 사람 이름은 `=?UTF-8?B?...?=` 로 인코딩. 도메인·systemd 서비스 이름은 이미 설치된 환경이 끊기지 않게 그대로 두었다.

## 8. 전공책 거래 정보와 글 수정

**문제** — 판매 글만으로는 "어디서, 언제" 만날지 댓글로 여러 번 주고받아야 했고, 올린 글은 고칠 수 없었다.

**해결**
- **거래 정보 버튼**: 📍 학교 장소(여러 곳) · 🗓 가능한 시간(요일 × 오전/점심/오후/저녁) · ⏰ 희망 시간. 사는 사람은 [이 조건으로 거래 요청]으로 장소·시간을 골라 문의 댓글을 바로 쓴다.
- **글 수정**: 모든 칸과 사진(빼기·순서 바꾸기·추가)을 한 트랜잭션으로 고친다 (`PUT /api/books/{id}`).

## 배운 점

- **판정은 한 곳에서**: 댓글 권한(`can_comment`), 정지 차단(`suspended_blocked`)처럼 규칙을 한 곳에 모으면 화면을 우회한 요청도 막히고 새 기능에서 빠뜨릴 일이 없다.
- **운영해 봐야 보이는 버그**: SIGPIPE 로 인한 서버 종료, 첫 수집이 다음 날로 밀린 것, 막힌 `confirm()` 은 모두 실제로 공개하고 나서야 발견했다.
- **실데이터로 검증**: 마감일 추출은 실제 공지 136건으로 돌려 보고 틀린 건을 원문과 대조해 규칙을 고쳤다.
- **기능을 더하는 것만큼 줄이는 것도 중요**: 멘토링 통합과 메뉴 정리로 같은 기능을 하나로 모으니 화면과 코드가 함께 단순해졌다.
- **사람 손을 덜 타게**: 스키마 자동 보정, 원클릭 공개, 자동 정리 덕분에 코드를 바꿔도 `make` 와 재시작만 하면 반영된다.
