# 서버 실행 방법 (리눅스 · 맥)

리눅스 노트북을 서버로 **계속 켜 두고** 쓰는 방법을 정리한 문서다.
(Windows 용 `.bat`·`.ps1` 실행 스크립트는 지웠다. Windows 에서는 `make` 로 빌드해 `server.exe` 를 직접 실행한다.)

같은 소스를 그대로 쓴다. 운영체제마다 다른 부분은 `src/platform.c` 와 `src/http.c` 안에서 나눠 처리하고,
바깥으로 나가는 HTTPS 요청(학교 공지 수집, Claude API, 임베딩 서비스)은 모두 libcurl 을 쓴다.

---

## 한눈에 보기

| 할 일 | 명령 |
| --- | --- |
| 처음 한 번: 패키지 설치, 빌드, DB 준비 | `scripts/setup-linux.sh` |
| 관리자 계정 만들기 | `scripts/run-server.sh --add-admin 20250001 운영자 비밀번호8자이상` |
| 시험 실행 (Ctrl+C 로 끈다) | `scripts/run-server.sh --port 8080` |
| **계속 켜 두기 (부팅 시 자동 시작)** | `scripts/install-service.sh` |
| 상태 / 로그 | `systemctl status sku14` / `journalctl -u sku14 -f` |
| 코드를 고친 뒤 반영 | `make && sudo systemctl restart sku14` |
| 서비스 지우기 | `scripts/install-service.sh --uninstall` |
| 지난 글 바로 정리 (보통은 서버가 1시간마다 알아서) | `scripts/run-server.sh --cleanup` |

명령은 모두 프로젝트 폴더(`SKU_14`)에서 실행한다.

## 1. 처음 한 번: 준비

```sh
git clone <저장소 주소>
cd TEAM_14/SKU_14
scripts/setup-linux.sh
```

`setup-linux.sh` 가 하는 일:

1. 패키지 설치 — gcc, make, MariaDB 클라이언트 라이브러리, libcurl, MySQL(또는 MariaDB) 서버
   - Ubuntu/Debian(`apt`), Fedora(`dnf`), macOS(Homebrew) 를 지원한다.
   - 다른 배포판은 같은 패키지를 직접 깔고 `scripts/setup-linux.sh --skip-packages`.
2. `make` 로 `server` 를 빌드한다.
3. `sku_contest` DB 가 **없을 때만** 만들고 스키마·학과 데이터를 넣는다. 이미 있으면 건드리지 않는다.
4. 서버 전용 DB 계정 `sku` 를 만들고 접속 정보를 `db.env` 에 저장한다 (권한 600, git 에 안 올라감).

> 리눅스의 MySQL root 는 비밀번호 대신 OS 계정으로 로그인하게(`sudo mysql`) 설정돼 있어서
> 서버가 root 로 접속할 수 없다. 그래서 전용 계정을 따로 만든다.

선택 옵션:

| 옵션 | 하는 일 |
| --- | --- |
| `--with-embed` | 딥러닝 임베딩용 파이썬 환경(`ml/.venv`)도 만든다. 약 1GB 를 내려받는다 |
| `--hosts` | `/etc/hosts` 에 `www.sku14.com` 을 이 컴퓨터로 등록한다 (이 컴퓨터에서만 유효) |
| `--skip-packages` | 패키지 설치를 건너뛴다 |

### 관리자 계정

```sh
scripts/run-server.sh --add-admin 20250001 운영자 비밀번호8자이상
```

`run-server.sh` 는 `db.env`·`smtp.env`·`ai.env` 를 읽어 환경변수로 넘긴 뒤 `./server` 를 실행한다.
`--crawl`, `--ai-analyze`, `--test-mail` 같은 일회성 명령도 같은 방법으로 쓴다.

### 인증 메일 (회원가입에 필요)

회원가입은 학교 메일(`@skuniv.ac.kr`)로 인증번호를 받아야 한다.
그 메일을 **보내는** 계정(Gmail)을 `smtp.env` 에 적어 둔다.

```
[smtp.env 의 Gmail]  ──인증번호──▶  [가입하는 학생의 @skuniv.ac.kr]
   보내는 사람 (1개)                    받는 사람 (가입자마다 다름)
```

1. 보낼 Gmail 계정에서 **2단계 인증**을 켠다.
2. <https://myaccount.google.com/apppasswords> 에서 **앱 비밀번호 16자리**를 만든다.
3. `smtp.env.example` 을 `smtp.env` 로 복사하고 위쪽 네 줄을 채운다.

   ```sh
   cp smtp.env.example smtp.env
   nano smtp.env
   ```
   ```
   SKU_SMTP_URL=smtps://smtp.gmail.com:465
   SKU_SMTP_USER=보낼계정@gmail.com
   SKU_SMTP_PASS=앱비밀번호16자리
   SKU_SMTP_FROM=보낼계정@gmail.com
   ```
   - `SKU_SMTP_PASS` 는 Gmail 로그인 비밀번호가 **아니라** 앱 비밀번호다. 띄어 써도 된다 (공백은 자동으로 뺀다).
4. 시험 메일을 보내 본다.

   ```sh
   scripts/run-server.sh --test-mail 받을주소@gmail.com
   ```

인증번호 메일이 안 오면 학교 메일함의 **스팸함**을 확인한다. 그래도 없으면 서버 로그 마지막 줄을 본다.
`535 ... not accepted` 는 앱 비밀번호가 틀린 것이다. 서비스로 띄운 뒤 `smtp.env` 를 고쳤으면 `sudo systemctl restart sku14`.

### AI 분석·추천 (선택, 유료)

`ai.env` 파일에 키를 한 줄 적는다 (git 에 안 올라감).

```sh
echo 'ANTHROPIC_API_KEY=sk-ant-...' > ai.env && chmod 600 ai.env
```

## 2. 시험 실행

```sh
scripts/run-server.sh --port 8080
```

브라우저에서 <http://localhost:8080>. `Ctrl+C` 로 끈다.

리눅스에서 1024 미만 포트(80)는 root 만 열 수 있어서, 손으로 띄울 때는 8080 을 쓴다.
(서비스로 등록하면 80 포트를 열 권한 하나만 따로 받으므로 80 으로 뜬다.)

터미널을 닫아도 계속 돌게 하려면 백그라운드로 띄운다.

```sh
./서버켜기.sh                 # = scripts/start-server.sh, 로그는 logs/server.err.log
./서버켜기.sh --bind-all      # 같은 와이파이의 다른 기기에서도 접속
./서버끄기.sh
```

## 3. 계속 켜 두기 (systemd 서비스)

노트북을 서버로 쓸 거라면 이것을 권한다.

```sh
scripts/install-service.sh
```

- **부팅하면 자동으로** 켜진다. 로그인하지 않아도 돈다.
- 서버가 죽거나, 부팅 때 MySQL 보다 먼저 떠서 접속에 실패해도 **5초 뒤 다시** 켜진다.
- 80 포트로, 다른 기기에서도 들어올 수 있게(`--bind-all`) 뜬다.
- 매일 06:00 에 학교 공지를 수집한다 (`sku14-crawl.timer`). 그 시각에 꺼져 있었으면 켜진 뒤 한 번 돌린다.
- `ml/.venv` 가 있으면 임베딩 서비스(`sku14-embed`)도 함께 등록한다.
- 서버는 root 가 아니라 **지금 로그인한 사용자 계정**으로 돈다.

| 옵션 | 하는 일 |
| --- | --- |
| `--port 8080` | 다른 포트 |
| `--local-only` | 이 컴퓨터에서만 접속 |
| `--no-crawl` | 매일 공지 수집을 등록하지 않음 |
| `--keep-awake` | 노트북 덮개를 닫거나 가만히 둬도 잠들지 않게 (아래 참고) |
| `--uninstall` | 등록한 것을 모두 지움 |

자주 쓰는 명령:

```sh
systemctl status sku14              # 돌고 있는지
journalctl -u sku14 -f              # 로그 실시간 보기 (Ctrl+C 로 나옴)
sudo systemctl restart sku14        # smtp.env / ai.env 를 고친 뒤
make && sudo systemctl restart sku14   # 코드를 고친 뒤
systemctl list-timers sku14-crawl   # 다음 공지 수집 시각
```

### 노트북이 잠들지 않게

노트북은 덮개를 닫거나 한동안 가만히 두면 절전 모드로 들어가 서버도 멈춘다.

```sh
scripts/install-service.sh --keep-awake
sudo reboot
```

- 덮개를 닫아도 꺼지지 않게 한다 (`/etc/systemd/logind.conf.d/sku14-keep-awake.conf`).
- 절전·최대 절전을 막는다 (`systemctl mask sleep.target suspend.target ...`).
- 화면만 꺼지고 컴퓨터는 계속 돈다. 되돌리려면 `--uninstall`.

전원 어댑터는 꽂아 둔다. 배터리를 오래 100% 로 두는 것이 걱정되면 제조사 설정(충전 한도 80% 등)을 켠다.

### 지난 글 자동 정리

서버는 켜질 때 한 번, 이후 **1시간마다** 기간이 지난 글을 지운다 (`src/cleanup.c`). 마감일 당일까지는 남는다.

| 대상 | 지우는 때 |
| --- | --- |
| 공모전 | 마감일이 지나면. 학교 공지는 수집할 때 본문의 "접수 기간" 등에서 마감일을 뽑아 둔다 |
| 마감일을 모르는 학교 공지 | 게시일로부터 60일 뒤 (`app_config` 의 `cleanup.no_deadline_days` 로 바꿀 수 있다) |
| 팀원 모집 | 마감(closed)했거나 마감일이 지나면 |
| 스터디 | 만들 때 정한 종료일이 지나면 (종료일을 안 정하면 지우지 않는다) |
| 판매 완료한 전공책 | 30일 뒤 |
| 알림 | 90일 뒤 |

자동 정리로 지운 공모전은 다음 수집 때 다시 올라오지 않는다. 관리자가 화면에서 직접 지운 학교 공지는 다음 수집 때 다시 올라온다.

## 4. 다른 사람이 접속하게 하기

`www.sku14.com` 은 실제로 산 도메인이 아니라서 `/etc/hosts` 에 등록한 **이 컴퓨터 안에서만** 열린다.
다른 사람은 아래 중 하나로 들어온다.

### 같은 와이파이 (가장 간단)

서비스는 기본으로 `--bind-all` 이라 바로 된다. 노트북 IP 를 확인하고,

```sh
hostname -I          # 첫 번째 값, 예: 192.168.0.23
```

다른 기기 브라우저에서 `http://192.168.0.23` 으로 연다.
방화벽(ufw)이 켜져 있으면 `sudo ufw allow 80/tcp`.

공유기가 노트북에 주는 IP 는 바뀔 수 있다. 공유기 관리 화면에서 **고정 IP(DHCP 예약)** 를 걸어 두면 편하다.

### 인터넷 어디서나: Cloudflare Tunnel (권장)

공유기 포트 포워딩 없이, 집 IP 를 드러내지 않고 공개 주소를 받는다.

```sh
# 설치: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/
cloudflared tunnel --url http://localhost:80
```

`https://xxxx.trycloudflare.com` 같은 주소가 찍힌다. 이 임시 주소는 cloudflared 를 다시 켤 때마다 바뀐다.
고정 주소가 필요하면 Cloudflare 계정에 도메인을 연결해 이름 있는 터널을 만들고 `cloudflared service install` 로 서비스 등록한다.

### 공유기 포트 포워딩

공유기 설정에서 외부 80 → 노트북 IP:80 으로 넘긴다. 집 공인 IP 가 드러나고, 통신사에 따라 80 포트가 막혀 있거나
공인 IP 가 바뀔 수 있다. 공개 운영이라면 HTTPS 가 없다는 점도 감안한다 (Cloudflare Tunnel 은 HTTPS 를 붙여 준다).

## 5. 문제 해결

| 증상 | 해결 |
| --- | --- |
| `make` 에서 `mysql.h: No such file` | `sudo apt install libmariadb-dev` (Fedora: `mariadb-connector-c-devel`) |
| `make` 에서 `curl/curl.h: No such file` | `sudo apt install libcurl4-openssl-dev` (Fedora: `libcurl-devel`) |
| 맥에서 `mysql.h` 를 못 찾음 | `brew install mariadb-connector-c`. MySQL 클라이언트를 쓰려면 `make MYSQL_CONFIG=$(brew --prefix mysql-client)/bin/mysql_config` |
| `Access denied for user 'sku'` | `scripts/setup-linux.sh --skip-packages` 를 다시 돌리면 계정 비밀번호를 새로 만들어 `db.env` 에 저장한다 |
| `Can't connect to local MySQL server through socket` | MySQL 이 꺼져 있다: `sudo systemctl start mysql` (또는 `mariadb`). 소켓 경로가 특이하면 `db.env` 의 `SKU_DB_HOST` 를 `127.0.0.1` 로 바꾼다 |
| `포트 80 바인드 실패 (Permission denied)` | 손으로 띄울 때는 `--port 8080`. 80 은 서비스로 등록하면 된다 |
| `포트 ... 바인드 실패 (Address already in use)` | 이미 서버가 떠 있다. `systemctl status sku14` 또는 `./서버끄기.sh` |
| `bash\r: No such file` / `$'\r': command not found` | Windows 에서 받은 파일을 옮긴 경우다. `sed -i 's/\r$//' scripts/*.sh *.sh` |
| 서비스가 계속 재시작됨 | `journalctl -u sku14 -n 50` 으로 원인 확인 |
