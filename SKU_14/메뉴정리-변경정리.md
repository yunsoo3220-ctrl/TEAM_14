# 메뉴 정리 · 서경스터디 (변경 정리, 2026-10-29)

사이드바 메뉴를 줄이고, 학과 관련 보기는 각 화면 안의 **탭**으로 옮겼다. 서비스 이름은 **서경스터디**로 바꿨다.

| 한 일 | 핵심 |
| --- | --- |
| 1. 사이드바 정리 | 공모전 목록 · 그룹 스터디 · 전공책 장터 · 내 모집 관리 · 채팅방 (+ 관리자에게만 관리자) |
| 2. 알림함 · 내 프로필 | 사이드바에서 뺐다. 상단바 오른쪽 🔔 와 **내 이름**을 눌러 연다 (보는 동안 그 단추가 강조된다) |
| 3. 학과 탭 | 공모전 목록 · 그룹 스터디 · 전공책 장터마다 **전체 / 내 학과 대상 / 학과별 추천** 탭 |
| 4. 내 모집 관리 | 예전 "팀원 모집" 메뉴. **내가 쓴 모집글 / 참여 중인 팀 / 모집글 둘러보기** 탭 |
| 5. 이름 변경 | 화면·메일·서비스 설명의 SKU14 → 서경스터디 |

---

## 1. 사이드바

| 전 | 후 |
| --- | --- |
| 공모전 목록, 내 학과 대상, 학과별 추천, 팀원 모집, 그룹 스터디, 전공책 장터, 알림함, 채팅방, 내 프로필 | 공모전 목록, 그룹 스터디, 전공책 장터, 내 모집 관리, 채팅방 |

- 비로그인: 공모전 목록 · 그룹 스터디 · 전공책 장터 세 개만 보인다 (내 모집 관리·채팅방은 로그인 후).
- 알림함 배지는 상단 🔔 에만, 채팅방 배지는 그대로 사이드바에 있다.

## 2. 화면 안의 탭

| 화면 | 전체 | 내 학과 대상 | 학과별 추천 |
| --- | --- | --- | --- |
| 공모전 목록 | `#/posts` | `#/mine` — 관리자가 대상 학과로 내 학과를 체크한 공모전 | `#/reco/{학과}` — 예전과 같은 자체 모델 추천 |
| 그룹 스터디 | `#/studies` | `#/studies/major` — 대상 학과가 내 학과인 스터디 | `#/studies/reco/{학과}` — 이름·소개·대상 학과를 학과 벡터와 비교 |
| 전공책 장터 | `#/books` | `#/books/major` — 판매 글의 학과가 내 학과인 책 | `#/books/reco/{학과}` — 제목·과목·저자·설명·학과를 학과 벡터와 비교 (판매 중만) |

- 학과별 추천은 학과를 고를 수 있고, 처음에는 내 학과(비로그인은 첫 학과)를 보여 준다. 카드에 관련도 게이지와 겹친 키워드가 붙는다.
- 내 학과 대상은 로그인이 필요하고, 소속 학과가 없는 관리자에게는 안내만 보인다 (공모전 탭은 예전처럼 로그인만 필요).
- 공모전 목록의 "내 학과가 쓸 수 있는 글만" 체크 상자는 내 학과 대상 탭과 겹쳐서 뺐다.

### 스터디 대상 학과 (새 열)

스터디에는 학과가 없어서 "내 학과 대상" 을 가릴 수 없었다. 그래서 **대상 학과**를 새로 만들었다.

- 스터디 만들기에 **대상 학과** 칸 (선택, 기본은 내 학과, "학과 무관" 가능). 목록 카드와 상세에 보인다.
- `study_groups.department_id` (NULL = 학과 무관, 학과가 지워지면 NULL).
- 이미 있던 스터디는 열을 처음 만들 때 **방장의 학과로 채운다** (만들기 화면의 기본값과 같게).

### 학과별 추천 (스터디·전공책)

공모전 추천과 같은 학과 벡터(TF-IDF + 임베딩, Rocchio)를 그대로 쓴다. 스터디·책은 학습 대상이 아니므로
새 함수 `ml_rank_texts` 가 **재학습 없이** 글마다 벡터를 만들어 비교한다 (임베딩은 한 번에 묶어서 요청, 서비스가 꺼져 있으면 TF-IDF 만).
기준은 공모전과 같은 **25점** (`ML_MIN_SCORE`).

## 3. 내 모집 관리 (`#/recruits`)

| 탭 | 내용 |
| --- | --- |
| 내가 쓴 모집글 `#/recruits` | 마감한 글도. 카드마다 팀 인원, **[팀원 찾기]**, **[모집 마감] / [다시 모집]** |
| 참여 중인 팀 `#/recruits/joined` | 글쓴이가 팀원으로 받아 준 글. 채팅방으로 바로 |
| 모집글 둘러보기 `#/recruits/all` | 예전 팀원 모집 목록 (키워드·상태 필터, 나와 맞는 순) |

- 모집글 상세의 돌아가기는 상황에 맞춘다: 내 글 → 내 모집 관리, 내 팀 → 참여 중인 팀, 남의 글 → 연결된 공모전 (없으면 둘러보기).
- 공모전 상세의 "이 공모전 팀원 모집" 과 [이 공모전으로 팀원 모집] 은 그대로다.

## 4. 이름 변경 (SKU14 → 서경스터디)

- 화면: 로고(서경**스터디**), 페이지 제목, 바닥글, 로그인 카드, AI 구조 소개.
- 메일: 가입 인증·참여 권유·메일 시험의 제목과 본문, **보낸 사람 이름** (한글이라 `=?UTF-8?B?...?=` 로 인코딩).
- 자체 모델 이름 (`/api/ml/info`), systemd 서비스 설명(Description).
- **그대로 둔 것**: 도메인 `www.sku14.com`, systemd 서비스 이름 `sku14`·`sku14-crawl`·`sku14-embed`, Message-ID 의 `@sku14.com`.
  주소·서비스 이름에는 한글을 쓸 수 없고, 바꾸면 이미 설치한 서비스·hosts 설정이 끊긴다.

## 5. API

| 메서드 | 주소 | 바뀐 점 |
| --- | --- | --- |
| GET | `/api/studies?dept={학과}` | 대상 학과가 그 학과인 스터디만 |
| GET | `/api/studies?reco={학과}` | 그 학과와 관련 있는 순, 항목마다 `score`·`terms` |
| POST | `/api/studies` | `department_id` (선택) |
| GET | `/api/studies`, `/api/studies/{id}` | 항목에 `department_id`·`department` |
| GET | `/api/books?reco={학과}` | 판매 중인 책을 그 학과와 관련 있는 순, 항목마다 `score`·`terms` |

## 반영 방법

```sh
make                             # 빌드
sudo systemctl restart sku14     # 서비스 재시작 (서버 코드가 바뀌었으므로 꼭 필요)
```

Windows 에서 `server.exe` 를 직접 띄웠다면 끄고 `make` 한 뒤 다시 띄운다 (돌고 있는 동안에는 `server.exe` 를 덮어쓸 수 없다).
